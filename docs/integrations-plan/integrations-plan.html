Integrations plan

Connecting the app to Shopify, payment services, banks, spreadsheets and other systems, and to Claude through an MCP plugin.

The goal

Today every transaction is typed into the app by hand. The goal is for sales, payments, fees and bank transactions to come in automatically from the systems the company already uses, as drafts that a person checks and posts.

Three ways to connect

1. Import from fileExcel / CSV from any bank, shop or system, with a column-mapping screen. Works with everything, fully offline.
2. Direct connectorsBuilt into the app for the most-used services (Shopify, WooCommerce, PayPal, Stripe, PayHere). One “Sync now” button.
3. Claude (MCP plugin)Claude reads and drafts records through our MCP server and connects to any other service that has an MCP server or API.
Shopify · WooCommerce · PayPal · Stripe · PayHere · Bank files · Excel · CRM · Email │ │ │ (1) file import (2) direct connector (3) Claude + MCP └────────────────────┼─────────────────────────┘ ▼ Cenango Accounting → DRAFTS → a person checks and posts │ Ledger · Reports · Tax return

Rules that never change

  • Drafts only. Nothing imported or created by Claude reaches the ledger until a person posts it.
  • No duplicates. Each outside record (a Shopify order, a bank line) is imported once, remembered by its own ID.
  • Everything is logged in the Activity Log, with its source (“via Shopify”, “via Claude”, “from file”).
  • Off by default. Each integration is switched on by an administrator. Keys are stored encrypted and can be removed at any time.
  • Offline stays the default. The internet is needed only while a connector syncs or Claude is used.

2The phases

Phase 1 — Import from file

Version 1.1 · about 2–3 weeks · works offline · needs nothing else
  • One Import screen: choose an Excel or CSV file, then match its columns to ours (date, description, amount, customer…). The mapping is saved per source, so next month is one click.
  • Imports bank statements (for reconciliation), sales, customers, vendors and opening balances.
  • Preview before import; duplicates skipped; everything lands as drafts.
  • Bank lines are matched automatically to open invoices and bills, with suggestions to confirm.

Phase 2 — Products, inventory, discounts and shipping

Version 1.2 · about 3–4 weeks · needed before Shopify products and stock
  • Products & services list: name, SKU, sale price, cost, income and expense accounts, tax code.
  • Stock quantities, cost of goods sold per item (average cost), stock adjustments, low-stock list.
  • Discount lines and shipping lines on invoices.

Phase 3 — Integrations framework and the Shopify connector

Version 1.3 · about 3 weeks · needs internet only while syncing
  • Settings → Integrations: connect, disconnect, last sync, errors. Keys stored encrypted.
  • Mapping screen: which bank receives payouts, which account gets fees, Shopify tax → our tax codes, Shopify products → our products.
  • Sync now (and optional hourly sync): orders, refunds, payouts and fees arrive as drafts. Each Shopify ID is imported once.
  • A summary after each sync: “12 orders, 1 refund, 2 payouts imported as drafts”.

Phase 4 — More connectors

Version 1.4 · about 1–2 weeks each
  • Built on the same framework, in the order customers need them, for example WooCommerce, PayPal, Stripe and PayHere.

Phase 5 — Claude MCP server and plugin

Version 1.5 · about 3–4 weeks · optional for each company
  • API keys in Settings, each tied to a user and role (a key can be read-only). Reachable from the same PC only.
  • MCP server installed with the app. Read tools: invoices, bills, customers, reports, account activity. Draft tools: invoice, bill, journal entry. No posting, voiding or deleting.
  • Claude plugin with ready-made skills: Month-end close · Import Shopify sales · Chase overdue customers · Prepare VAT return · Explain a report.
  • With Shopify's (or another service's) own connector added to Claude, Claude can move data between them and our app, e.g. “Import this week's Shopify orders as draft invoices”.

3Safety, privacy and what we need

Safety and privacy

  • Drafts only from every source; a person posts. Claude can never post, void or delete.
  • Audit trail: every imported or Claude-created record shows its source in the Activity Log and on its transaction details page.
  • Undo: an import can be removed as a whole while its records are still drafts.
  • Keys: Shopify, PayPal and API keys are stored encrypted, never shown again after saving, and can be revoked.
  • Privacy notice: connectors send nothing except the requests needed to fetch data. When Claude is used, the data it reads is sent to Claude (Anthropic) to answer the question. Customers are told this clearly, and both can stay switched off.
  • Offline default: without connectors or Claude, the app never uses the internet.
